# Home v4 主页面视觉修复记录

日期：2026-07-22  
状态：已实现并通过开发态回归；Home v4 仍保持 development preview / non-shipping

## 已确认问题

1. **右墙与画框不共面。** 旧 Display 资产以 Home v3 为透视参考，只对六个正视画框做矩形缩放和约 `±0.5°` 旋转；Home v4 的右墙深度线则明显向右下收敛。
2. **墙面接缝制造了错误的第二墙角。** Home v4 在画布 `x≈845` 有一条高对比竖缝，恰好穿过左列三个画框。空框本身不是缺陷；缺陷是接缝、画框和墙面没有共享几何。
3. **进食状态重复拥有食盆。** Home 底图绘有干粮碗，`eat` Portrait 又自带一只碗，运行时叠加后成为双碗。
4. **桌面纪念品缺少物理落脚。** 所有类型共用正视方形锚点，旧校验只检查粗略矩形范围，没有检查物件底部是否落在桌面梯形内。
5. **场景文字和 Treat 控件压过插画。** 状态文案在地毯上的对比度不足；Treat 控件使用过宽胶囊，遮挡窗台叙事。
6. **静态 QA 的纪念品出现黑色竖线。** 构建脚本在 `contain` 缩放时使用了不透明黑色补边，旋转后暴露为与素材无关的伪影。

## 修复决定

- Home Display 的透视基准更新为 Home v4。
- 右墙 Display 最终使用以柜子顶面为参考的六组投影四边形；远列缩小，每个画框上下边在柜子给出的 `10.8°–13.9°` 方向范围内收敛。画框底图与运行时明信片使用同一组四角数据。
- 移除 `x=832..858` 的错误接缝，并把墙角迁移到与窗台下分割一致的 `x=768`；墙角重建为贯通顶部的单一暗阶，不再复制会产生亮色反弹边的原缝色差。
- 新增仅供 `eat` 使用的 `interior-foreground-eat`：只修补底图干粮碗区域，其他活动仍使用有水碗和食盆的正常底图。
- 纪念品锚点收回桌面内部，按 `pin` / `charm` 类型压缩到桌面透视，并增加浅托盘与接触阴影。
- 明信片缩略图移除不可读的小字；状态文案获得低对比纸面承托；Treat 控件缩为以鱼干为主的紧凑点击目标，无鱼干时完全隐藏。
- 纪念品构建的 `contain` 补边显式设为透明，避免旋转后的黑边；桌面 QA 区域禁止出现不透明纯黑像素。
- 运行时截图脚本显式等待每次 IndexedDB 状态写入后的页面重载，并等待 Chrome 退出后再清理临时目录，避免状态串拍和清理竞态。

## 回归门槛

- 每个画框必须由显式四点数据定义，四点都在 `x=768` 墙角右侧；上下边斜率必须落在柜子参考的 `50/262–65/262` 范围内，远列面积必须小于近列，且不得退化成上下边平行的仿射平行四边形。
- Home Display 必须声明 Home v4 为唯一透视参考。
- 纪念品的接触点必须位于桌面四边形内。
- `eat` 底图只能在食盆修补区域与普通底图不同。
- 上下墙角必须共同落在 `x≈768`，且 `x≈845` 不得重新变成更强的结构性竖线。
- empty / partial / full / departure-note 四种 470×900 Display 状态必须分别得到 `0/2/6/2` 张明信片、`0/2/3/3` 件纪念品，且空 Treat 控件均不可见。
- `eat` Home 合成只允许出现猫自带食盆和独立水碗，不允许底图干粮碗重现。

## 第二轮诊断：点击层与墙面物理模型

### 复现

- partial / full / departure-note 三种运行时状态中，明信片与纪念品按钮均存在，但按钮中心的 `elementFromPoint` 命中 `div.window`。
- 原因是开发态 `.window` 被扩展到整张 1200×1600 画布并处于 `z-index: 9`，高于 `z-index: 7` 的 Display；它没有声明指针穿透。
- `interior-foreground` 的生成源同时包含两条竞争的垂直墙线：上墙在 `x≈845`，窗台下的真实墙角在 `x≈768`。旧画框从 `x=730` 开始，因此跨越下方墙角；统一 `8.5°` 又小于桌边和地脚线给出的约 `9.96–12.2°`。

### 修复

- 整画布 `.window` 改为 `pointer-events: none`，仅 `.windowsill` 恢复 `pointer-events: auto`。这样 Treat 仍可收取，Display 不再被透明容器遮挡。
- 采用确定性的受控平面重建，不重新生成整间屋子：移除 `x≈845` 的错误缝，将原水彩缝的局部色差迁移到 `x=768`，与窗台下墙角共享同一条垂直世界边。
- 画框左边界移到 `x=790` 之后，全部位于右墙；当时右墙剪切角更新为 `11°`（第三轮已被柜子基准四点投影取代）。桌面纪念品使用独立的 `10°` 桌面角度，不再错误复用墙面常量。

### 新增回归信号

- 运行时报告检查明信片和纪念品的中心命中目标，并用真实鼠标事件分别打开明信片详情和纪念品详情。
- Home 资产检查分别扫描上墙与窗台下的最强垂直边，要求二者和 manifest 的 `cornerX=768` 相差不超过 3 px，同时旧 `x=845` 缝不得更强。
- Display 检查要求所有画框位于墙角右侧；第三轮进一步升级为四点、面积与柜子方向检查，并继续校验空白、部分、完整和离家字条四种 470×900 状态。

## 第三轮诊断：双墙缝与柜子基准投影

### 原型决策

- 先制作了 A「当前仿射网格」、B「柜边单斜率」、C「柜子基准投影」三个 dev-only 低保真变体。
- 采用 C：墙角左边界固定为 `x=768`；两列三排都在右墙内；远列缩小；每个画框使用四角投影；柜子顶面的后沿 `65/262` 与前沿 `50/262` 作为方向范围。
- 原型验证后删除临时 HTML 路由。采用方案的静态说明保留在 `docs/art/candidates/home-wall-prototype/layout-plan--variant-c.png`。

### 复现与根因

- 旧墙角重建把原接缝的有符号色差整体迁移到 `x=768`。上墙的暗边约为 `-22.4`，紧邻亮边约为 `+17.3`，因此视觉上仍是深浅两条缝；旧 QA 只统计绝对梯度，会把这种“暗—亮脊线”误判为正确单缝。
- 旧 Display 的六个框只共享 `skewY(11°)`。它能让横边朝右下倾斜，却强制每个框上下边平行，无法表达柜子表现出的远端缩小与投影收敛。
- “画框素材已经透视、运行时又二次变形”被排除：框资产和明信片各自只应用一次变形，真正缺陷是二者共享了过浅的仿射模型。

### 修复

- 先在 `x=760..777` 重建纸面水彩 wash，清掉原有暗亮脊线；随后从 `x=768` 加入单向暗阶，并用 40 px 的低梯度阴影慢慢恢复右墙亮度。暗边从 `y=0` 连续到地脚线，邻近区域不再形成第二条浅色缝。
- `postcardDisplaySlots` 从矩形尺寸与 `skewY` 改为六组显式四角坐标，并记录仅用于内容方向的局部倾角。运行时按钮用四边形裁切，内部图像沿同一方向变形。
- 构建脚本加入四点单应投影采样，把六个独立水彩画框和静态 QA 明信片真正投影到对应四边形；不再用 `skewPngY` 生成平行四边形。
- production / candidate manifest 都记录 `cabinet-referenced-quadrilaterals` 和柜子前后沿斜率，避免未来退回某个孤立角度常量。

### 新增回归信号

- Home 资产检查同时测量边缘极性：`x=768` 从天花板、上墙到地脚线必须持续为暗边，右侧 12 px 内任何亮色返回边都不得超过阈值。
- Home 单元测试和 Display 资产检查要求每个 slot 都是四点投影，所有点位于右墙，远列面积更小，上下边落在柜子参考方向内且不平行。
- 四种 470×900 运行时状态重新截图；实际鼠标点击仍能打开明信片和纪念品详情。
