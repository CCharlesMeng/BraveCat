## Executive result

- The only production-approved character art is Minho's six-pose 1024×1024 RGBA set. It is complete and must not be regenerated by the remaining batches.
- The current home is still constructed from CSS gradients and geometry, fish emoji, character navigation tokens, and a CSS paper note. Home v3 has a strong 1200×1600 candidate replacement, and home v4 completed the supported memo stand plus sill-safe Treat tray with measured 6.2/7.1 px minimum margins. Both remain untracked, non-shipping, and visually unapproved.
- All eight starter-item image paths exist in data, but no corresponding files exist under `public/assets/items`, and the UI ignores `imageSrc` in favor of the first Chinese character of each item name. Shop v1 produced a dedicated eight-item candidate family. Postcard-gifts v1 independently produced a second, byte-different eight-item family despite the intended non-overlap; shop v1 must be designated canonical before promotion, and pack v1 must reuse that one family.
- Pack v1 completed a non-shipping base/rim layer system, three slot anchors, 342/382 px derivatives, manifest, QA, and 390/430 reviews. It is pending visual approval. Its 1536 masters are deterministic upscales from a 1024 generated source, its item layers are review proxies, and it has no 320 px proof.
- Postcard-gifts v1 completed blank Postcard, stack, envelope/pocket, Treat, and starter-item candidates plus reviews and immutable checks. It did not produce a postmark asset, a Scene-unavailable fallback, or an explicit Album-empty review. Destination souvenir content is still undefined: `STARTER_CATALOG.souvenirs` is empty and selection always returns `souvenirIds: []`.
- The repository contains 20 destinations / 48 runtime scene derivatives, but `LANDMARK_SCENES_SHIPPING_ELIGIBLE` is false and production builds strip all scene files. A production player therefore sees the CSS mountain/sun placeholder for every postcard. Separately, the candidate tree has 25 destinations / 61 scenes; the newest 13 are still awaiting visual, composite, and rights review. More scene generation does not by itself close these gates.
- The installed-app icon family is a thick-outline flat-vector envelope containing an invented orange-white cat. It is inconsistent with both the approved Minho identity and the locked watercolor art direction. This is the highest-priority unassigned, immediately generatable batch.
- The loading screen, first-run presentation, paper surface treatment, and utility glyph family remain unassigned and can be generated independently without touching active candidate directories.

## Locked constraints used by this audit

- Display name and domain language follow `CONTEXT.md`; use Home, Pack, Postcard, Portrait, Scene, Treat, Windowsill, Shop, Album, Companion, Note, and Souvenir semantics.
- Locked art intensity is B: restrained low-saturation watercolor, thin warm gray-brown definition, warm-white paper grain, generous negative space, no neon, hard digital gradients, flat-vector treatment, thick black outlines, pseudo-text, or baked UI.
- Postcard/Scene master format is 1200×900, landscape 4:3, 8-bit sRGB, opaque.
- Portrait pose masters are 1024×1024 straight-alpha RGBA, with zero RGB in fully transparent pixels and at least 64 px safe margin.
- Item/Souvenir masters are 512×512 straight-alpha RGBA, with at least 48 px safe margin and legibility at a 46–48 px UI display.
- Runtime postcard layer order remains `scene → portrait → copy → postmark`; text, dates, prices, counts, destination names, and labels stay live.
- Runtime must remain local/offline; no production image API calls.
- Current app width is 320–470 px. Acceptance evidence must include 390×844 and 430×932, and narrow-screen checks must include 320 px.

## CSS/UI visuals intentionally retained as code

The audit checked these CSS geometries and does **not** recommend rasterizing them:

- focus rings, button hit areas, drawer backdrop, drawer handle, card borders, rounded corners, shadows, disabled opacity, native select, numeric unread badge, and status text;
- developer-only clock controls;
- layout separators and scroll containers.

They are interaction chrome, not illustrations. Replacing them with baked images would hurt accessibility, responsiveness, or localization. Thematic CSS substitutes—room scenery, fish plate, Postcard placeholder, paper texture, postmark, character tokens, and Unicode empty art—are covered above.
