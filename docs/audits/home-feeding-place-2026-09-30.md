# 首页饭碗、水碗与吃饭位置补齐

用户复审指出首页缺少饭碗和水碗。这是上一轮 I01–I04 验收遗漏：不能因为猫窝、隧道和动画都能加载，就认定小猫的生活区域完整。

## 确认的根因

- A/B/F 正式主题的 `slots` 与默认 Cat Items 只有 rest/play，已有 feed 类型并未注册正式用品，因此双碗没有进入场景、发布清单或离线预缓存。
- 三套已批准的 `piece--feeding-set--candidate-v01.png` 实际存在；旧 feed 预留坐标与后来冻结的 rest 猫窝范围相交，直接照搬仍会在猫窝里吃饭。
- Minho eat 动画本身已经画了一只碗，不能再简单叠放一组碗，否则会出现第三只碗；沿用旧朝向还会让前爪压进右侧水碗。

## 修复

- 使用现有 Cat Item / feed 机制注册 `feed-daily-bowls`，A/B/F 默认常驻，gaze/sleep/play/eat 均显示。既有规范化逻辑自动补齐旧存档，无 schema 迁移或新养成数值。
- 三套批准母版原样保留，只裁掉 alpha=0 的外部画布，转为无损 WebP。来源 SHA、裁切框与派生 SHA 纳入 `home-release/manifest.v1.json`；32 个家资源通过同一批准字节门禁。
- 左饭碗、右水碗，在碗内合成少量食物和水面高光，便于小尺寸识别。这是静态场景表现，没有引入饥饿、补水或消耗逻辑。
- A 的双碗位于猫窝右侧、地毯后方的地板；B 位于猫窝与柜子之间的地板带；F 位于下层地毯右侧地板。feed 和 rest/play 三组物件矩形互不相交。
- eat 改为朝右接近左侧饭碗，前爪不进入水碗；B 按较窄的地板带使用 300px 猫框，A/F 仍为 360px。resolver 复用主题已有猫框宽度，不增加新适配字段。
- 仅对当前 Minho 带碗 eat 贴片应用合成裁切，保留猫与嘴部，用常驻用品承担双碗；动画/poster 字节不变，不裁切其他形象。原猫窝、隧道、gaze 窗台、鱼干入口和旧归档保留。
