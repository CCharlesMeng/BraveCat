# 本地优先保留，云账号可选

无账号仍可完整游玩：存档留在设备本地（web 为 IndexedDB），导出 / 导入照旧，断网或未配置后端时所有玩法不受影响。构建期配置了 API 地址（web 为 `VITE_API_BASE_URL`）时，客户端首次进入静默创建游客账号（不透明 bearer token，服务端只存哈希），云存档同步与生成次数余额作为增强能力接入；玩家看不到注册流程，也不需要看到。

本决定取代 ADR-0002 的「无账号」部分：商业化需要跨设备同步，且生成次数严格服务端记账（ADR-0006），账号不可避免。ADR-0002 的「本地优先」部分被继承：本地存档仍是游玩的事实来源，云端只是带 schema 版本护栏的 last-writer-wins 黑盒副本；启动时按 exportedAt 较新者胜比较，会话内本地未保存改动优先推送，以云端覆盖本地前必须先把本地导出为下载备份——数据安全优先于同步便利。

## Consequences

- 游客账号在首次联网时静默创建，凭证存本地；token 丢失即账号丢失，跨设备携带账号依赖 Phase 2 的微信 / Apple / 手机号绑定。
- 未配置 API 地址的构建不发起任何云端请求，行为与纯本地版完全一致；云同步失败只降级为状态提示，不阻塞玩法。
- 云端存档 schemaVersion 高于客户端时拒绝下发并提示升级（426），旧客户端也不得覆盖更新版本的云端存档（409），不做静默降级。
- 冲突不做字段级合并：接受两台设备同时离线游玩时较旧一方被覆盖（有导出备份兜底），换取无向量时钟的极简实现。
- 存档导出 / 导入作为本地优先的兜底能力永久保留，不因云同步上线而移除。
