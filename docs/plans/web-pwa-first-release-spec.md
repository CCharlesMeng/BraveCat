# 咪游记 Web/PWA 首发执行规格

日期：2026-09-29。依据：本轮用户四轮产品答复，最后明确“都按照推荐进行”。状态：产品方向已收口；本文件是实施输入，不是实现完成或发布证明。已确认决定与工程默认值分别列出。

## 1. 已确认首发范围

- 中国大陆 Web/PWA，免费完整体验。
- 核心循环：领养、收取小鱼干、小铺、行囊、自主旅行、明信片、纪念品、归家并再次出发。
- 当前主线：内置 Minho、A/B/F 家主题、猫窝/隧道。继续保留当前已有多猫能力；多只 CatProfile 共享家与相册，内置 Portrait 只有 Minho，不能把姿势数当形象数。
- 小故事为《值夜观星》《雾港看归船》两组，每组四幕；属于同批发布必做项。
- 小故事是自主旅行中的自然奇遇，无专属物品门槛，相关行囊物品提高倾向。
- 普通旅行为主，故事偶尔出现；优先未经历的故事，避免连续重复；不设首日强制保底。
- 四幕沿旅行时间依次寄回；离线照常推进，回来补齐已到时的内容；收齐后随时整组回看。
- 仅本机存档+导入导出；账号、云同步、短信、照片 AI 生成、支付/会员均后置。保留已有后端实现，首发构建不启用相应入口和请求。
- 其他端、其余故事、扩展用品/窗景、推送、matrix3d 真透视均不成为本次首发阻塞。
- 当前素材用户审批已完成，使用 `docs/art/reviews/all-existing-assets-approval-2026-09-29.json` 的准确字节与路径，不再对同一素材重复索要批准。

## 2. 玩家可观察规则

1. 玩家为猫准备普通行囊，小猫按原有节奏自主出发；玩家没有启动故事或催促下一幕按钮。
2. 出发时一次决定普通旅行或故事旅行，并锁定完整内容和时间。刷新、重新打开或修改系统时间不会重新抽故事。
3. 普通旅行保持原有目的地、1–2 张来信与纪念品规则；故事旅行固定四幕，不在四幕内部再次抽取缺幕或替换顺序。
4. 故事用虚构地点与独立故事身份表示；不混入真实地标名单或虚报“到访地点”。
5. 首幕抵达后相册出现该次小故事；未抵达的幕不提前展示画面和剧情。第四幕抵达后显示尾页/印记，允许随时顺序回看与保存已收到的单张明信片。
6. 故事没有额外 Treat、纪念品、下一关或任务奖励。故事中的鱼等画面道具不自动变成真实游戏货币或库存。
7. 重复故事属于另一次真实旅行，不能覆盖旧相册记录；收藏总览可合并同一故事的入口，并保留各次旅行的日期和来信。
8. 离线一次跨过多幕或返程时，按锁定时间补齐；每幕只入册一次，尾页只解锁一次，行囊只结算一次。
9. 用户保留导出备份能力；更换设备或清除浏览器数据的恢复依赖此前导出的文件。界面应说明这一点，不能声称有云端备份。

## 3. 初始工程默认值（可调，不是用户逐项指定）

目的：把“偶尔、偏向、避免重复”变成可实现和验证的规则。上线前可根据连续试玩调整数值，不能改变上面的产品承诺。

| 参数/规则 | 初始值 |
|---|---|
| 合格出发的基础故事概率 | 20% |
| 带有与当前可选故事对应的物品 | 故事概率提高至 30%，多件不叠加超过上限 |
| 物品与故事映射 | 小望远镜 `small-telescope` →《值夜观星》；小鱼饼 `fish-biscuit` →《雾港看归船》 |
| 指定故事的相对权重 | 对应物品使其权重 ×2；两个物品都带则两者各 ×2 |
| 未经历优先 | 有尚未完成且当前未被其他猫锁定的故事时，优先从这些故事中选择 |
| 重复 | 两组都完成后可再次经历；有替代故事时排除最近完成的一组 |
| 节奏间隔 | 同一只猫一次故事后，至少完成一次普通旅行再允许新故事；没有符合条件的故事则走普通旅行 |
| 并行猫 | 当前被其他猫锁定的故事暂不重复分配；同一时刻多猫出发按稳定顺序处理，锁定结果入存档 |
| 旅程时长 | 沿用 2–24 小时与已有时长物品效果，不另设故事额外等待 |
| 四幕时刻 | 旅程经过 20%、40%、60%、80% 时寄回；100% 时归家 |

概率适用于满足资格且未被真实地标心愿优先占用的出发，不承诺每五次必有一次，也不保证首日一定遇到。

### 与普通车票的兼容

真实地标车票保留既有强引导：先按普通 Wish 的 80% 命中 / 15% 同区域 / 5% 意外分支判断；命中明确心愿地时保留普通旅行，不再用故事覆盖它。

没有有效心愿地，或车票发生绕路/意外时，才在符合故事资格的情况下检查上述故事概率。未选中故事则继续原普通路线；选中时记录为虚构故事旅行，不能把原抽出的真实地点当成实际到访或发放该地点纪念品。

这是兼容旧心愿承诺的初始工程方案：带车票不会彻底禁用自然故事，但总体故事机会较无车票低。实际概率与边界应有确定性测试，不把普通 Wish 的 80% 当成故事概率。

### 物品结算与其他效果

- 本次复用零食/玩具，不新增专属故事引导物。因此旧概念“专属引导物未命中返还”没有对应的新物品，不应扩大成所有零食免消耗。
- 玩具返还、零食按原规则消耗、普通车票按原规则消耗，保持已存在的经济行为。
- 小相机的额外普通来信效果不把故事变成五幕；铃铛、姿势和随机文案效果不改写已经批准的故事画面和顺序。
- 物品说明区分普通旅行效果与故事倾向，避免承诺“携带即必达”。

## 4. 素材与呈现边界

两组选定基线分别来自：

- `docs/art/candidates/cinematic-v6/night-watch-stargazing/selected-four-act-v01/`
- `docs/art/candidates/cinematic-v6/mist-harbor-returning-boats/selected-four-act-v01/`

现有故事画面已经包含 Minho。首发消费这些批准画面时不能再叠一只 Portrait；文案、邮戳、边框仍在客户端离线渲染。普通地标明信片继续 Scene + Portrait 合成。实现需明确两种配方并记录对 ADR-0001 的扩展，不能把整幅故事画面伪装成无猫 Scene。

故事条目关联实际出行 CatProfile，保留名字、旅行 ID 与内容版本；本次不提供上传自定义形象，未来形象扩展不得追溯改写已收故事。

低保真稿的旧限制是生产处理记录，不重开用户审批。选择批准字节、归一化尺寸、派生发布文件、登记哈希及避免重复猫合成均属于工程任务；不得静默覆盖批准母版。

## 5. 状态、存档与离线

当前 GameState 与 SaveDocument 均为 v4；新增故事需同步维护版本和迁移，不只修改 Web UI。

- 保存故事 ID/内容版本、所属猫/旅行、四幕绝对时刻、固定画面/文案引用，以及用于重复控制的已完成记录。
- 继续用已持久化 tripSeed；故事选择锁定后只读取计划，不因页面渲染或相册打开再次调用随机选择。
- 相册和冷却只由可信本地旅行结果推进，不按查看次数推进；进度恢复与相册记录一致。
- 旧 v4 普通旅行继续按旧计划完成；迁移只补故事初始状态，不能重新抽目的地或丢失纪念品。
- 导入损坏/未知版本文件时保留当前存档；成功导入原子替换，所有猫与故事一并恢复。
- 仅使用已有本地存档设施，不引入首发服务端依赖。生产构建禁用账号/生成/付费入口，但保留后续代码。

## 6. 执行顺序与完成证据

| 顺序 | 交付 | 关键验收 |
|---|---|---|
| 1 | 故事领域/目录、旅行规划和存档迁移 | 随机边界、Wish 优先、无候选回退、重复间隔、多猫与 v4 迁移 |
| 2 | 四幕揭晓与归家结算 | 离线跨幕、跨返程、刷新不重抽、重复推进不重复发放 |
| 3 | 相册小故事与单卡保存 | 逐幕可见、未揭晓不泄露、尾页/回看、导入后恢复、无重复猫 |
| 4 | 正式素材与生产构建接入 | 只引入选定版本、实际资源可加载、PWA离线缓存、所有用户审批引用准确 |
| 5 | 首发入口与本地备份说明 | 无账号/上传/支付入口及请求，备份/恢复功能清楚可用 |
| 6 | 发布候选验收 | 核心完整循环+故事循环、窄屏/离线/SW升级、分享导出、真实设备 |
| 7 | 正式部署 | 发布版本、HTTPS/资源路径、回滚、用户支持与适用发行材料 |

确定性测试优先覆盖行为和边界，不为纯文档或机械映射添加镜像测试。浏览器/真机用于实际呈现、安装、权限和离线验收，不能用单测替代。

## 7. 发布外部依赖

免费静态首发不依赖短信、云账号、AI 服务和支付。实际托管目标/域名、适用发行材料及既有地标的第三方权利文件仍需核实；用户素材批准不能捏造成机构许可。到部署阶段应先完成可检查的发行包，再处理确实需要用户提供的配置或材料。

本文件只确认产品范围与执行方案，不将尚未运行的故事代码、真实设备验收或正式部署标为完成。
